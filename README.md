# 原版 SWS 固件

Arduino 工程入口：仓库根目录的 `SmartWebServer.ino`

本目录保留原版网页与控制协议实现，不包含 Vue 静态资源或 Vue API 适配层
这里的“原版”指原网页实现，保留仓库已经完成的协议修复，并非回退到历史上游版本

- 配置文件：`Config.h` 和 `Extended.config.h`
- 网页首页：设备地址 `/`
- 直接用 Arduino IDE 打开本目录的工程即可编译，不需要 Node 或 Vue
- 使用 Arduino CLI：`arduino-cli compile --warnings all --fqbn esp8266:esp8266:nodemcuv2 .`（ESP8266），或 `arduino-cli compile --warnings all --fqbn esp32:esp32:esp32 .`（ESP32）
- 安装独立浏览器测试依赖：`npm ci --prefix tests --ignore-scripts`；预览服务：`node demo/server.cjs`

固件源码位于根目录和 `src/`；原版项目说明保存在 `README.upstream.md`，许可证为 `LICENSE`

## 网页配网

- 连接设备热点，进入网络页面并输入管理密码
- Wi-Fi 已开启时进入页面会自动搜索，同时可点击刷新手动搜索；重新打开开关时直接连接当前已知网络，没有已知网络时先展示搜索列表
- 已连接网络单独显示并带勾选，名称下方保留 dBm，点选可查看 IP 和修改网络设置
- 点选其他网络后弹出连接窗口，输入密码再点击连接，无需重启，取消不会改变当前连接
- 密码框右侧可显示或隐藏密码，无密码网络自动识别，不再使用密码相关的复选框
- 设备保留当前已保存网络的密码，再次选择该网络时可直接连接或填写新密码替换，状态接口只返回是否已记住密码
- 已提交的密码在当前页面内按网络名称暂存，失败后再次选择同一网络可恢复输入，取消未提交的输入不会记住，刷新或离开页面后清除
- 单次连接分阶段断开及重新配置，短暂失败状态不会立即终止；每轮至多发起两次连接，总等待最多 30 秒
- 当前已保存且开启的网络启动失败或意外断线后，先等待 2 秒；后台连接仍失败时按 5、10、20、40、60 秒的间隔持续重试，成功后重置间隔，关闭开关后停止
- ESP8266 SDK 明确报告密码错误或发现地址配置冲突时，停止自动重试并提示修改；未验证的新密码不覆盖设备原有凭据，连接新网络失败后可恢复先前已知网络
- 后台重连与单次连接时序分别由 `StationReconnect.h` 和 `StationConnection.h` 管理，不依赖网页保持打开；后台重连期间仍可刷新列表、换网或关闭 Wi-Fi，用户操作优先且保留热点入口
- 查看已连接网络后原样保存不会断开连接，也不会重复写入相同的设置
- 验证中的新网络参数保持独立，其他页面同时保存设置也不会提前写入未验证的密码；连接成功后才替换设备原有凭据
- 网络状态读取连续失败后按 5、10、20、30 秒降低重试频率，恢复联网或重新进入页面时立即重新读取；手动配网会取消旧的状态读取
- 隐藏网络可通过其他网络手动添加，在窗口中选择需要密码或无需密码
- 点选新网络默认自动获取 IP，需要固定 IP 时可展开窗口中的网络设置
- 设备热点与路由器连接可以同时使用，配网时会保留热点作为恢复入口
- 连接路由器后热点会跟随路由器信道，手机可能短暂断线，重新连接即可
- 热点与路由器应使用不同网段，页面会检查静态地址并在连接后检查 DHCP 地址
- 更改热点名称或地址后，需要用新名称或新地址重新访问
- 配网页面支持网络名称最多 31 字节、STA 密码最多 63 字节、设备热点密码最多 31 字节，中文会占用多个字节
- Wi-Fi 名称、密码和开关保存在设备中，重启后继续使用

## 网络负载保护

- `Config.h` 中 `NETWORK_LOAD_GUARD` 默认 `ON`，`OFF` 可关闭本次新增的网络负载保护
- ESP8266 的独立适配层位于 `src/lib/wifi/webServer/GuardedServer.h`，共用限制位于 `src/lib/wifi/NetworkBudget.h`，页面及 OnStep 命令处理函数保持独立
- 热点和局域网共用同一个网页服务，按请求依次处理，响应发送完成后主动关闭连接，不再占用服务等待浏览器断开
- 未发送请求的连接等待最多 1 秒，读取请求头设为 1 秒超时，单次写入设为 1.5 秒超时，响应开始输出 15 秒后不再继续发送后续分段
- 剩余堆低于 10000 字节时，新的网页请求返回 HTTP 503 和 `Retry-After: 2`，新的 TCP 命令连接关闭，本次请求不执行设备操作
- Wi-Fi TCP 命令入口每轮最多读取 64 字节、处理 1 条完整指令，保留半帧与未读数据，标准端口已收到的批量指令不会因分轮处理而被一秒连接期限截断
- 原命令任务周期仍为 5 毫秒，实际响应还受串口等待和其他任务影响；已对照原版回放连续坐标查询、坐标设置与 GOTO、脉冲导星和跟踪命令，NINA/ASCOM 实机并发及导星延迟仍需刷入验证
- 状态轮询失败后由原有逻辑退避重试，控制指令不因保护机制自动重放，页面加载失败可重新点击标签
- `node tests/network-load-guard.cjs` 使用已安装的 ESP8266 2.4.2 内核状态机进行本地模拟，验证多客户端排队、低内存恢复、慢连接、批量及半帧命令和开关关闭行为，可用 `SWS_ESP8266_CORE` 指定内核目录
- 本地模拟与固件编译不能替代实机压力测试，刷入后仍需验证手机和电脑同时访问、热点和局域网同时访问、慢客户端断线后的恢复

## 界面与原始逻辑分离

界面保持固件内置，不需要单独部署前端，也不增加运行时语言切换。多语言继续使用原始的 `Config.h: DISPLAY_LANGUAGE → src/locales/Locale.h → Strings_xx.h`；`L_us` 仍使用英文与英制单位。原始辅助页面直接写出的 DP、sec、x 等文字保留原样。

| 修改内容 | 维护位置，相对于 src |
| --- | --- |
| 暗红、灰黑配色 | `pages/ui/Palette.h` |
| 公共布局与手机适配 | `pages/ui/Styles.h` |
| 页面分区 HTML | `pages/ui/Layouts.h` |
| 跟踪开关、倍率下拉框、坐标表单增强 | `pages/ui/Controls.h` |
| 位置与限位编辑卡片、方向与时区选择、单一停放入口 | `pages/ui/Editors.h` |
| 侧栏、手机导航与标签切换 | `pages/ui/Navigation.h` |
| 界面资源分段输出 | `pages/ui/Presentation.cpp` |
| Wi-Fi 样式、HTML、浏览器脚本与渲染入口 | `pages/network/ui/` |
| Wi-Fi 配网处理与状态 | `pages/network/NetworkWifi.cpp` |
| 界面文字 | `locales/Strings_*.h` |
| 各卡片内容、动态数据和设备条件 | 原来的 `pages/*/*Tile.h` 与 `*Tile.cpp` |

`Appearance.h` 保留为公共界面的包含入口；原来的页面处理函数只调用界面入口或分区模板，继续读取设备状态并处理参数。选中状态使用 `data-selected`，不再根据按钮的 RGB 颜色判断。配色保留 SWS 原有的 `COLOR_*` 配置覆盖方式。

确认按钮通过 `Text.h` 将文案放在 HTML 属性中，事件从属性读取，避免语言中的单引号破坏脚本。直接嵌入脚本的语言宏使用 `SWS_JS_TEXT` 在编译时转义，不增加语言字典、运行时查询或额外接口。

上游更新仍可能改动卡片的参数、设备条件或 HTML 标识，这些部分不能完全独立。合并时保留上游的业务修复，再核对下面的接入点；不要把新上游整份页面覆盖成本地旧页面：

1. 原始路由、登录验证、页面参数处理及设备命令；新增坐标输入沿用 mount 接口，Wi-Fi 配网扩展仍在 `/net-wifi`。
2. 页面头部的 `pageAppearance()`、普通标签的 `servePageShell()`，以及分区模板的输出位置。
3. 卡片 `id`、表单 `name` 和 AJAX 键值；`Controls.h` 对已有控件的代理依赖这些标识。
4. 已确认的后台修复：轴参数边界校验、附件目标边界、编码器第二轴恢复默认值、长语言标签缓冲区。它们保留在所属模块，不能作为样式覆盖处理。

## 页面加载与刷新性能

- 公共样式和控件脚本分别由 `/sws-ui.css`、`/sws-ui.js` 提供，浏览器在导航外壳与内容页之间复用缓存。地址包含编译时间和 `DISPLAY_LANGUAGE`，新固件或不同语言不会继续使用旧地址；设备数据、登录状态和表单页面不缓存。
- 资源仍直接从固件 Flash 分段读取，每段最多 1024 字节，不把整份资源复制到 RAM；新增两个静态资源入口，保留原设备接口。
- 打开导航外壳时复用后台已发现的设备信息，实际内容页才执行完整状态读取。带参数的请求和 POST 仍进入原参数处理流程，设备未发现时保留原错误页面。
- 状态刷新使用单次定时器，每次响应完成后按原配置安排下一次刷新；同一页面最多一个状态请求，避免慢连接不断堆积。页面完全加载后才开始刷新，隐藏标签和切换页面时暂停，回到前台立即更新。
- 普通命令和按住移动的命令正在发送时，下一次状态刷新暂缓；命令参数、顺序和停止操作不变。请求失败后逐步延长状态刷新间隔，成功后恢复，不自动重发操作命令。
- 只有数据变化时才改写读数、选中状态和禁用状态，避免反复触发页面重排及控件观察器。网络页在隐藏或离开时也停止发起状态请求。
- `node tests/page-performance.cjs` 检查实际资源字节数、浏览器缓存和版本地址、七个页面的导航分派、原命令脚本缓冲区、慢请求去重、重复状态不改写页面、命令优先、隐藏暂停和失败退避。测试产物仍位于 `tests/output/`。

这些检查验证传输量及调度行为；实机加载和操作耗时还受 Wi-Fi、串口和主控响应影响，需刷入新固件后确认。

## ESP8266 网络活动灯与赤经轴抱闸

保护逻辑全部运行在 SmartWebServer，不修改 OnStep 固件。网页只提交设置、解除锁定和重试停止请求，关闭网页后后台采样和保护仍继续运行。

| 引脚 | 映射及输出 | 行为 |
| --- | --- | --- |
| IO2 | 原 LED_STATUS_PIN，低电平亮灯 | 业务收发闪烁，失联保持原连接提示，关闭活动指示后恢复原有显示 |
| IO5 | RA_BRAKE_PIN，LOW 抱闸，HIGH 松闸 | 编译关闭时从引脚初始化起 HIGH；编译开启时上电 LOW，通过检查后才 HIGH |

在 Config.h 中设置 RA_BRAKE_PROTECTION。OFF 隐藏保护开关，不采样、不自动停止、不拦截命令，IO5 保持 HIGH；ON 启动保护模块并显示网页开关。引脚初始化前的电平由硬件决定，IO5 的外部下拉电阻仍需保留。IO5 不再兼任第二轴编码器 A，虚拟 GPIO 也避开本模块占用的引脚。

编译开启时的运行顺序：

1. 上电先 LOW 抱闸并锁定经过 SWS 的新运动。输出任务或采样任务启动失败时保持 LOW。读取网页开关和已保存的故障原因，记录缺失、损坏、取值异常或存储提交失败都按存储故障锁定处理。首次安装没有故障记录时同样需要人工解除锁定，不自动创建无故障记录。
2. 网页保护开启、没有保存的故障锁定，并且新鲜有效的驱动无故障反馈连续保持至少 500 ms，才输出 HIGH 并允许新运动。网页开关上电为关闭时保持 LOW。
3. 正常运行、跟踪、移动和普通静止都保持 HIGH，单独 ST 不启动抱闸流程。驱动故障、无效反馈、失联、反馈超过 1 秒未更新或关闭网页保护时，锁定本次事件原因，禁止新运动，并保存到 NV。
4. 每次事件只启动一次统一停止：发送 :Q# 终止 GOTO、手动移动、导星和回零，再发送 :Td# 关闭跟踪。分别记录 Q 的完整写入结果和 Td 的接受结果。任一步失败都显示停止未完成，只有用户点击“重试停止”才重新发送。
5. 停止后保持当前 GPIO 电平并持续采样，网页保护关闭期间也继续采样。只有两条命令均成功，且停止流程结束之后收到至少两帧新鲜有效 ST、两帧跨度至少 250 ms，才输出 LOW 抱闸。故障触发帧、旧帧、重复帧都不计入；无效、过期或不带 ST 的反馈清除未完成确认。没有 1.5 秒到时强制抱闸。
6. 抱闸后保持故障锁定。失联无论发生在 HIGH 还是 LOW，都保持当前电平，不重新启动停止流程，也不清除故障。反馈正常、刷新页面、重新打开开关及重新上电均不会自动松闸。
7. 只有用户明确点击“解除锁定”，网页保护开启，并且新鲜、无故障、带 ST 的反馈连续保持至少 500 ms，才清除已保存的故障和旧停止确认，输出 HIGH、解除运动锁定。不会恢复原先的跟踪或移动，清除故障存储失败时拒绝解除锁定。

状态只使用现有 :GXU1#，采样周期为 250 ms，单次读取超时为 200 ms。八个字段必须符合 ST、OA、OB、GA、GB、OT、PW、GF 的位置定义；七类故障中任一置位均按故障处理。0、未知文本、超时、格式错误及 ST 至 PW 全置位的通信故障组合均不能作为有效静止确认。

本版按现有反馈实施软件保护，不增加“驱动初始化/电流配置/使能已完成”“主控全部运动已结束”或抱闸释放时序这三个前置检查。GXU1 无法证明这些条件，ST 也不是机械轴速反馈，因此这些状态及机械安全性没有得到验证。电流配置完成不代表已经测得实际保持电流。

所有经过 SWS 串口命令通道的入口共用拦截：网页、TCP 第三方连接和其他本机控制来源都在真正发送前判断锁定。锁定期间只放行诊断查询、停止和通信速率设置，未知扩展及校验帧也拒绝转发。锁定和复位时旧 TCP 连接会断开，丢弃其缓冲命令和半帧；第三方软件需要重新连接。SWS 无法拦截直接连接 OnStep 的 USB、其他网络端口或主控本地入口。

网页使用独立的 /board-io 接口。BOARD_IO_SETTINGS 保存活动灯和保护开关，RA_BRAKE_FAULT 单独保存本次锁定原因，切换开关不清除故障。故障写入和人工清除都立即提交到底层存储，提交完成且读回一致才报告成功，不等待普通设置的后台延迟保存。POST action=reset 请求解除锁定，action=retry-stop 请求重试停止；不满足条件返回 409。GET 返回状态、锁定原因和两条停止命令各自的结果。存储写入失败会提示并限速重试，不反复启动停止流程；清除失败或清除期间反馈失效时立即尝试恢复原故障并保持锁定。正常时隐藏故障操作；等待停止确认时只显示“重试停止”，确认抱闸后只显示“解除锁定”。

这些检查确认的是存储接口返回的提交结果，不能保证闪存擦写过程中突然掉电时的数据完整性，仍需实机断电验证。若重启后记录缺失或校验损坏，程序保持抱闸并要求人工解除锁定。
