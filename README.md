# 原版 SWS 固件

Arduino 工程入口：仓库根目录的 `SmartWebServer.ino`

本目录保留原版网页与控制协议实现，不包含 Vue 静态资源或 Vue API 适配层
这里的“原版”指原网页实现，保留仓库已经完成的协议修复，并非回退到历史上游版本

- 配置文件：`Config.h` 和 `Extended.config.h`
- 网页首页：设备地址 `/`
- 直接用 Arduino IDE 打开本目录的工程即可编译，不需要 Node 或 Vue
- 使用 Arduino CLI：`arduino-cli compile --clean --jobs 1 --warnings all --fqbn esp8266:esp8266:nodemcuv2 .`（ESP8266），或 `arduino-cli compile --clean --jobs 1 --warnings all --fqbn esp32:esp32:esp32 .`（ESP32），两个目标依次验证
- 本地保留测试和演示工具时，可安装浏览器测试依赖：`npm ci --prefix tests --ignore-scripts`；预览服务：`node demo/server.cjs`

固件源码位于根目录和 `src/`；原版项目说明保存在 `README.upstream.md`，许可证为 `LICENSE`

## Git 跟踪范围

仓库跟踪固件入口、配置、`src/` 下的固件源文件和各级 README 说明，同时保留 `LICENSE` 与 `.gitignore`。

演示脚本、`tests/`、`tools/`、编辑器缓存、依赖及编译产物只保留在本地，不加入版本控制。README 中的测试、预览和差异检查命令适用于本地已保留相应工具的环境；仅检出仓库的环境可直接使用 Arduino 编译固件。

## 网页配网

- 连接设备热点，进入网络页面并输入管理密码
- 进入网络页只读取状态，点击刷新才搜索；首次开启且没有已知网络时自动搜索，重新打开已知网络则直接连接
- 已连接网络单独显示并带勾选，名称下方保留 dBm，点选可查看 IP 和修改网络设置
- 点选其他网络后弹出连接窗口，输入密码再点击连接，无需重启，取消不会改变当前连接
- 密码框右侧可显示或隐藏密码，无密码网络自动识别，不再使用密码相关的复选框
- 设备保留当前已保存网络的密码，再次选择该网络时可直接连接或填写新密码替换，状态接口只返回是否已记住密码
- 已提交的密码在当前页面内按网络名称暂存，失败后再次选择同一网络可恢复输入，取消未提交的输入不会记住，刷新或离开页面后清除
- 连接和失败清理以 10 月 16 日的 05a60f41 为对照：SWS 一次完成配置和连接，允许 SDK 在 25 秒窗口内处理短暂失败；超时只断开路由器并清空 SDK 当前连接目标，保持 AP+STA 模式，不关闭 STA 或重启已有热点
- 已保存且开启的网络仍会上电自动连接；SDK 可自行恢复短暂断线，SWS 在启动回退或掉线后等待 30 秒补充一次后台连接，明确超时后停止搜索，等待手动重试，关闭开关后停止
- ESP8266 SDK 明确报告密码错误或发现地址配置冲突时提示修改；未验证的新密码不覆盖设备原有凭据，连接新网络失败后仍保留先前已知网络，可手动重新连接
- 后台重连与单次连接时序分别由 `StationReconnect.h` 和 `StationConnection.h` 管理，不依赖网页保持打开；后台重连期间仍可刷新列表、换网或关闭 Wi-Fi，用户操作优先且保留热点入口
- 查看已连接网络后原样保存不会断开连接，也不会重复写入相同的设置
- 验证中的新网络参数保持独立，其他页面同时保存设置也不会提前写入未验证的密码；连接成功后才替换设备原有凭据
- 网络状态读取连续失败后按 5、10、20、30 秒降低重试频率，恢复联网或重新进入页面时立即重新读取；手动配网会取消旧的状态读取
- 隐藏网络可通过其他网络手动添加，在窗口中选择需要密码或无需密码
- 点选新网络默认自动获取 IP，需要固定 IP 时可展开窗口中的网络设置
- 设备热点与路由器连接可以同时使用，配网时会保留热点作为恢复入口
- 连接路由器后热点会跟随路由器信道，手机可能短暂断线，重新连接即可
- 热点与路由器应使用不同网段，页面会检查静态地址并在连接后检查 DHCP 地址
- 更改热点名称或地址后，需要用新名称或新地址重新访问
- 配网页面支持网络名称最多 31 字节、STA 密码最多 63 字节、设备热点密码最多 31 字节，中文会占用多个字节
- STA 开关意图在返回接受响应之前单独写入并提交存储，重启后恢复开关；待验证的新网络名称和密码仍只在成功后保存，连接失败不覆盖原有可用凭据
- DHCP 主机名由 `HOST_NAME` 转为小写，当前为 `onstep-sws`，启动连接及网页开启 STA 时均在 STA 开启后、发起连接前应用；该名称不依赖 mDNS 开关，mDNS 名称仍由 `MDNS_NAME` 单独配置

## 原生网页与网络接口

网页和 TCP 服务恢复原始 SWS 的内核接口与处理方式，已删除实验性网络防护模块及配置开关，不再保留自定义 WebServer 子类、堆阈值、提前断开或分轮命令限制。

- ESP8266 直接使用 ESP8266WebServer，ESP32 使用 WebServer；路由仍通过 www.on 登记，参数处理与回复格式沿用原接口
- 标签通过原生链接直接打开完整页面，表单和浏览器前进后退由浏览器处理，取消 iframe 外壳、view 参数注入与加载队列
- 页头、标题和选中标签由原版 pageHeader 直接输出，样式先在 head 加载，公共脚本不再重建导航；普通点击立即使用原生链接，只有正在执行运动停止时才等待停止队列完成，最多等待 5 秒，超时留在原页供重试
- 基础样式、网络样式和公共脚本由浏览器缓存；图标直接随页头输出，避免外部 SVG 到达后补绘，Wi-Fi 使用 sendContent_P 按至多 1024 字节发送 Flash 内容；以太网保留原生字符串发送方式
- 网络活动回调只记录时间，不直接执行抱闸停止或 GPIO 更新，由原有 OnTask 任务每 20 ms 处理
- 本地模拟与源码回归不能替代 ESP-07S 的实际无线及串口耗时验证

## 界面与原始逻辑分离

界面保持固件内置，不需要单独部署前端，也不增加运行时语言切换。多语言继续使用原始的 `Config.h: DISPLAY_LANGUAGE → src/locales/Locale.h → Strings_xx.h`；`L_us` 仍使用英文与英制单位。原始辅助页面直接写出的 DP、sec、x 等文字保留原样。

| 修改内容 | 维护位置，相对于 src |
| --- | --- |
| 暗红、灰黑配色 | `extensions/ui/Palette.h` |
| 公共布局与手机适配 | `extensions/ui/Styles.h` |
| 页面分区 HTML | `extensions/ui/Layouts.h` |
| 原生跟踪开关和倍率的事件绑定、坐标表单增强 | `extensions/ui/Controls.h` |
| 位置与限位编辑卡片、方向与时区选择、单一停放入口 | `extensions/ui/Editors.h` |
| 侧栏、手机导航与标签切换 | `pages/Page.*`、`extensions/ui/Navigation.h`、`Icons.h` |
| 界面资源分段输出 | `extensions/ui/Presentation.cpp` |
| Wi-Fi 样式、HTML、浏览器脚本与渲染入口 | `extensions/network/ui/` |
| Wi-Fi 配网处理与状态 | `extensions/network/NetworkWifi.cpp` |
| 界面文字 | `locales/Strings_*.h` |
| 各卡片内容、动态数据和设备条件 | 原来的 `pages/*/*Tile.h` 与 `*Tile.cpp` |

`extensions/ui/Appearance.h` 是公共界面的包含入口；原来的页面处理函数只调用界面入口或分区模板，继续读取设备状态并处理参数。选中状态使用 `data-selected`，不再根据按钮的 RGB 颜色判断。配色保留 SWS 原有的 `COLOR_*` 配置覆盖方式。

确认按钮通过 `Text.h` 将文案放在 HTML 属性中，事件从属性读取，避免语言中的单引号破坏脚本。直接嵌入脚本的语言宏使用 `SWS_JS_TEXT` 在编译时转义，不增加语言字典、运行时查询或额外接口。

上游更新仍可能改动卡片的参数、设备条件或 HTML 标识，这些部分不能完全独立。合并时保留上游的业务修复，再核对下面的接入点；不要把新上游整份页面覆盖成本地旧页面：

1. 原始路由、登录验证、页面参数处理及设备命令；新增坐标输入沿用 mount 接口，Wi-Fi 配网扩展仍在 `/net-wifi`。
2. 页面头部的 `pageHead()`、原生 pageHeader 输出与链接，以及分区模板的输出位置。
3. 卡片 `id`、表单 `name` 和 AJAX 键值；`Controls.h` 对已有控件的代理依赖这些标识。
4. 已确认的后台修复：轴参数边界校验、附件目标边界、编码器第二轴恢复默认值、长语言标签缓冲区。它们保留在所属模块，不能作为样式覆盖处理。

## ESP8266 网络活动灯与赤经轴抱闸

保护逻辑全部运行在 SmartWebServer，不修改 OnStep 固件。网页只提交设置、手动解锁和重试停止请求，关闭网页后后台采样和自动逻辑仍继续运行。

| 引脚 | 映射及输出 | 行为 |
| --- | --- | --- |
| IO2 | 原 LED_STATUS_PIN，低电平亮灯 | 业务收发闪烁，失联保持原连接提示，关闭活动指示后恢复原有显示 |
| IO5 | RA_BRAKE_PIN，LOW 抱闸，HIGH 松闸 | 编译关闭时从引脚初始化起 HIGH；编译开启时上电 LOW，通过检查后才 HIGH |

在 Config.h 中设置 RA_BRAKE_PROTECTION。OFF 隐藏保护开关，不采样、不自动停止，IO5 保持 HIGH；ON 启动保护模块并显示网页开关。引脚初始化前的电平由硬件决定，IO5 的外部下拉电阻仍需保留。IO5 不再兼任第二轴编码器 A，虚拟 GPIO 也避开本模块占用的引脚。

编译开启时的运行顺序：

1. 上电沿用初始 LOW 抱闸电平。输出任务或采样任务启动失败时保持 LOW。只读取活动灯和网页保护开关，不读取或保存故障记录；设置存储不可用时采用默认开启设置，仍由实际驱动反馈决定能否松闸。
2. 网页保护开启、本次运行没有故障锁定，并且新鲜有效的驱动无故障反馈连续保持至少 500 ms，才输出 HIGH 松闸。网页开关上电为关闭时保持 LOW。重新上电后重新查询驱动，正常反馈满足条件即可松闸，无须为上一次运行的故障人工复位。
3. 正常运行、跟踪、移动和普通静止都保持 HIGH，单独 ST 不启动抱闸流程。驱动故障、无效反馈、失联、反馈超过 1 秒未更新或关闭网页保护时，在内存中记录并锁定本次事件原因，不写入存储。
4. 每次事件自动启动统一停止：发送 :Q# 终止 GOTO、手动移动、导星和回零，再发送 :Td# 关闭跟踪。分别记录 Q 的完整写入结果和 Td 的接受结果。任一步失败都显示停止未完成，并从本次尝试结束起每隔 2 秒自动重新发送两条命令，每轮最多尝试 3 次（含首次），两条均成功后提前结束重试；成功后只等待有效静止反馈，不重复发送。等待期间保持原抱闸电平，达到次数上限后停止自动发送，“重试停止”按钮可立即启动新一轮最多 3 次的尝试，手动解锁会取消后续自动重试。
5. 停止后保持当前 GPIO 电平并持续采样，网页保护关闭期间也继续采样。只有两条命令均成功，且停止流程结束之后收到至少两帧新鲜有效 ST、两帧跨度至少 250 ms，才输出 LOW 抱闸。故障触发帧、旧帧、重复帧都不计入；无效、过期或不带 ST 的反馈清除未完成确认。没有 1.5 秒到时强制抱闸。
6. 抱闸后保持本次运行的故障锁定。失联、超时或反馈无效时，无论此前为 HIGH 松闸还是 LOW 抱闸，都保持当前电平，不重新启动停止流程，也不清除故障。反馈正常、刷新页面及重新打开开关均不会自动松闸；重新上电则重新走启动查询流程。
7. 本次运行发生故障后，不会因恢复正常反馈而自行解除锁定。用户可以点击常驻的“手动解锁”，不检查状态就立即松闸并暂停自动逻辑，再按需要打开“自动锁定”。不会恢复原先的跟踪或移动，手动操作不读写存储。

状态只使用现有 :GXU1#，正常反馈采样间隔为 250 ms，无效反馈后每秒探测一次，单次读取超时为 200 ms。八个字段必须符合 ST、OA、OB、GA、GB、OT、PW、GF 的位置定义；七类故障中任一置位均按故障处理。0、未知文本、超时、格式错误及 ST 至 PW 全置位的通信故障组合均不能作为有效静止确认。

保护开启的固件中，赤经轴驱动状态显示复用同一保护采样，不再额外查询。失联、查询失败或反馈超过 1 秒时显示未知，避免继续显示旧的正常状态；通信恢复后持续刷新，不因连续失败而停止更新。普通静止标记不会遮住驱动故障提示。

本版按现有反馈实施软件保护，不增加“驱动初始化/电流配置/使能已完成”“主控全部运动已结束”或抱闸释放时序这三个前置检查。GXU1 无法证明这些条件，ST 也不是机械轴速反馈，因此这些状态及机械安全性没有得到验证。电流配置完成不代表已经测得实际保持电流。

手动解锁与自动锁定分开操作。手动解锁直接输出 HIGH，不检查主控连接、驱动反馈或 ST，不发送停止命令，同时清除本次故障及旧停止记录，并暂停本次运行的自动逻辑。此后失联或驱动异常不会自动改变手动解锁电平；重新打开自动锁定才恢复原自动流程。手动解锁只作用于本次运行，不写入存储，也不恢复之前的跟踪或移动；重新上电仍先 LOW，再按已保存的自动开关设置启动。

SWS 不再按抱闸状态过滤网页、TCP 或串口命令，也不会因抱闸锁定、复位或手动解锁而断开 TCP 连接或丢弃半帧。模块只管理抱闸输出、反馈采样和故障停止流程；OnStepX 自身负责接收和处理所有控制入口的运动命令。

网页使用独立的 /board-io 接口。BOARD_IO_SETTINGS 只保存活动灯和自动开关，故障状态仅存在内存中，不再读写 RA_BRAKE_FAULT，升级前留下的旧故障记录也不参与判断。切换开关和刷新网页不会清除本次故障，重新上电会重新查询驱动。POST action=manual-unlock 请求直接手动解锁，action=retry-stop 请求重试停止。原 action=reset 接口为兼容保留，仍要求正常、带 ST 的新鲜反馈连续保持 500 ms；界面不再显示该操作。GET 返回模式、状态、锁定原因和两条停止命令各自的结果。设置保存失败会提示，但不撤销已启动的停止流程。手动解锁按钮与带开关的自动锁定始终显示；等待停止确认时额外显示“重试停止”。

## Wi-Fi 扫描与后台重连

历史追溯：1218fc3f 在 10 月 16 日加入网络页自动搜索，1846e2e3 在 10 月 17 日加入扫描可中断后台连接，后续迁移保留这两条路径。ESP8266 内核 2.4.2 的 scanNetworks 在 STA 正在关联时会主动断开 STA，因此仅恢复 HTTP 服务或超时清理并不能消除扫描与连接的相互干扰。本次修正配网 UI 与 NetworkWifi 扫描入口，保留原生 Wi-Fi、HTTP、TCP 接口及当前连接策略。

进入网络页、切页返回及连接完成都只读取状态，保持当前 AP 和 STA 连接。搜索仅由刷新按钮或没有已知网络时首次打开开关触发。后台连接和手动连接期间均暂停扫描，ESP8266 设备端还检查 SDK 的关联状态，覆盖上电关联及掉线恢复尚未进入网页状态机的阶段。

手动修改连接或热点设置先完成参数校验，只有有效且需要执行的操作才中断后台重连。热点参数及开关状态没有变化时直接返回成功，不重启 DHCP、不写入存储。延迟应用热点设置前再次检查路由器网段，地址冲突时保留原热点配置。

`/net-wifi` 的 POST `action=scan` 使用 `start=1` 启动扫描，后续轮询使用 `start=0`。旧页面传入 `automatic=1` 的新扫描请求返回 409，并提示点击刷新；这类请求不操作无线接口。无扫描任务时的过期轮询返回 409，不会再启动扫描或断开 STA。未提供 `start=1` 的启动请求同样返回 409，避免旧页面把未标记的自动搜索当成手动操作。
